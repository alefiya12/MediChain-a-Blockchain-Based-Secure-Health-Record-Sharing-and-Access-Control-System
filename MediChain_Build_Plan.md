# MediChain — Phased Build Plan

> **Audience:** Antigravity (AI coding agent). Follow phases **in order**. Do not start a phase until the previous phase's **Exit Criteria** pass.
> **Project:** MediChain — Blockchain-Based Secure Healthcare Record Sharing and Access Control System
> **Stack:** React.js + Bootstrap (frontend) · Node.js + Express + MongoDB (backend) · Solidity + Hardhat + ethers.js v6 (blockchain) · Polygon Amoy Testnet

---

## 0. Ground Rules and Architecture Decisions (read first)

These decisions are final. Do not deviate unless something is impossible.

### 0.1 Hybrid architecture

| Concern | Where it lives |
|---|---|
| Medical files (PDF/JPG/PNG) | Backend disk (`backend/storage/`), **encrypted at rest (AES-256-GCM)**. Never on-chain. |
| Users, record metadata, requests, audit logs | MongoDB |
| SHA-256 hash of each file, doctor verification flag, access permissions | Solidity smart contract (source of truth for permissions) |
| Transaction signing for patient/doctor/admin actions | User's **MetaMask wallet in the browser** (ethers v6 `BrowserProvider`) |

### 0.2 Who signs what (important)

- **Patient** signs: `registerRecord`, `respondToRequest` (grant/reject), `revokeAccess`.
- **Doctor** signs: `requestAccess`.
- **Admin** (contract owner) signs: `verifyDoctor`, `rejectDoctor`.
- The backend **never holds user private keys**. It only *reads* the chain (via a read-only JSON-RPC provider) to enforce authorization, and stores `txHash` returned by the frontend after confirmation.

### 0.3 Authorization rule for viewing a record (critical)

A doctor may download a file **only if both** are true:
1. MongoDB says the doctor `isVerified === true`, **and**
2. The contract call `hasAccess(patientWallet, doctorWallet)` returns `true` (checked by the backend at request time).

### 0.4 Integrity rule

- Backend computes `SHA-256` of the **plaintext file** on upload → `0x`-prefixed 32-byte hex.
- Patient signs `registerRecord(recordId, fileHash)` on-chain.
- Verification: backend decrypts file → recomputes hash → calls contract `getRecord(recordId)` → compares. Result: `VERIFIED` or `TAMPERED`.
- `recordId` (bytes32) = `ethers.id(<MongoDB record _id string>)` (keccak256 of the string).

### 0.5 Fixed versions and conventions

- Node.js **20 LTS**, npm 10+.
- Use **Hardhat 2.x** (`hardhat@^2.22`) with `@nomicfoundation/hardhat-toolbox` (bundles ethers v6, chai, coverage). Do **not** use Hardhat 3.
- Solidity `0.8.24`, EVM version `paris` (safe for Amoy), OpenZeppelin Contracts `^5`.
- Frontend: **Vite + React 18** (not CRA, which is deprecated). JavaScript only (no TypeScript).
- Backend: CommonJS or ES modules — **use ES modules** (`"type": "module"`) consistently.
- Network: Polygon Amoy — **chainId 80002**, hex `0x13882`, RPC `https://rpc-amoy.polygon.technology`, explorer `https://amoy.polygonscan.com`, currency `POL`.
- Ports: backend `5000`, frontend `5173`, MongoDB `27017`.

## 2. Data Model (MongoDB / Mongoose)

### `User`
| Field | Type | Notes |
|---|---|---|
| `name` | String, required | |
| `email` | String, required, unique, lowercase | |
| `passwordHash` | String, required | bcrypt, 12 rounds |
| `role` | enum `patient` \| `doctor` \| `admin` | |
| `walletAddress` | String, lowercase, unique, sparse | validated with `ethers.isAddress` |
| `patientId` | String, unique, sparse | `MC-P-` + 6 chars from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`; only for patients |
| `isActive` | Boolean, default true | |
| `timestamps` | | |

### `DoctorProfile`
`user` (ref User, unique), `licenseNumber` (unique), `specialization`, `hospital`, `experienceYears`, `status` (`pending` \| `approved` \| `rejected`, default `pending`), `rejectionReason`, `verifiedBy` (ref User), `verifiedAt`, `verifyTxHash`.

### `MedicalRecord`
`patient` (ref User), `title`, `category` (enum: `prescription`, `lab_report`, `diagnosis_report`, `scan_report`, `discharge_summary`), `description`, `originalName`, `mimeType`, `sizeBytes`, `storedName` (random UUID filename), `iv`, `authTag` (base64, for AES-GCM), `fileHash` (0x + 64 hex), `recordIdOnChain` (bytes32 hex), `chainStatus` (`pending` \| `confirmed`, default `pending`), `txHash`, `blockNumber`, `timestamps`.

### `AccessRequest`
`patient` (ref User), `doctor` (ref User), `reason`, `status` (`pending` \| `granted` \| `rejected` \| `revoked`), `requestTxHash`, `responseTxHash`, `revokeTxHash`, `respondedAt`, `revokedAt`, `timestamps`. Unique partial index on `(patient, doctor)` where `status` in `pending`/`granted`.

### `AuditLog`
`actor` (ref User), `actorRole`, `action` (enum below), `patient` (ref User, optional), `doctor` (ref User, optional), `record` (ref MedicalRecord, optional), `txHash`, `metadata` (Mixed), `createdAt`.

Audit actions: `USER_REGISTERED`, `DOCTOR_REGISTERED`, `DOCTOR_APPROVED`, `DOCTOR_REJECTED`, `RECORD_UPLOADED`, `RECORD_CHAIN_CONFIRMED`, `RECORD_VERIFIED`, `RECORD_TAMPER_DETECTED`, `RECORD_VIEWED`, `ACCESS_REQUESTED`, `ACCESS_GRANTED`, `ACCESS_REJECTED`, `ACCESS_REVOKED`.

## 3. Smart Contract Specification (`MediChain.sol`)

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@openzeppelin/contracts/access/Ownable.sol";

contract MediChain is Ownable {
    enum AccessStatus { None, Pending, Granted, Rejected, Revoked }

    struct Record {
        bytes32 fileHash;
        address patient;
        uint64  timestamp;
        bool    exists;
    }

    mapping(bytes32 => Record) private records;                              // recordId => Record
    mapping(address => bool) public verifiedDoctors;
    mapping(address => mapping(address => AccessStatus)) public accessStatus; // patient => doctor => status

    event DoctorVerified(address indexed doctor, address indexed admin);
    event DoctorRejected(address indexed doctor, address indexed admin);
    event RecordRegistered(bytes32 indexed recordId, address indexed patient, bytes32 fileHash, uint64 timestamp);
    event AccessRequested(address indexed patient, address indexed doctor, uint64 timestamp);
    event AccessGranted(address indexed patient, address indexed doctor, uint64 timestamp);
    event AccessRejected(address indexed patient, address indexed doctor, uint64 timestamp);
    event AccessRevoked(address indexed patient, address indexed doctor, uint64 timestamp);

    constructor() Ownable(msg.sender) {}

    // ---- Admin ----
    function verifyDoctor(address doctor) external onlyOwner {
        require(doctor != address(0), "Invalid address");
        verifiedDoctors[doctor] = true;
        emit DoctorVerified(doctor, msg.sender);
    }

    function rejectDoctor(address doctor) external onlyOwner {
        verifiedDoctors[doctor] = false;
        emit DoctorRejected(doctor, msg.sender);
    }

    // ---- Patient: records ----
    function registerRecord(bytes32 recordId, bytes32 fileHash) external {
        require(!records[recordId].exists, "Record already registered");
        require(fileHash != bytes32(0), "Empty hash");
        records[recordId] = Record(fileHash, msg.sender, uint64(block.timestamp), true);
        emit RecordRegistered(recordId, msg.sender, fileHash, uint64(block.timestamp));
    }

    function getRecord(bytes32 recordId)
        external view returns (bytes32 fileHash, address patient, uint64 timestamp)
    {
        Record memory r = records[recordId];
        require(r.exists, "Record not found");
        return (r.fileHash, r.patient, r.timestamp);
    }

    function verifyRecordHash(bytes32 recordId, bytes32 candidateHash) external view returns (bool) {
        Record memory r = records[recordId];
        require(r.exists, "Record not found");
        return r.fileHash == candidateHash;
    }

    // ---- Doctor ----
    function requestAccess(address patient) external {
        require(verifiedDoctors[msg.sender], "Doctor not verified");
        require(patient != address(0) && patient != msg.sender, "Invalid patient");
        AccessStatus s = accessStatus[patient][msg.sender];
        require(s != AccessStatus.Pending && s != AccessStatus.Granted, "Request exists");
        accessStatus[patient][msg.sender] = AccessStatus.Pending;
        emit AccessRequested(patient, msg.sender, uint64(block.timestamp));
    }

    // ---- Patient: consent ----
    function respondToRequest(address doctor, bool approve) external {
        require(accessStatus[msg.sender][doctor] == AccessStatus.Pending, "No pending request");
        if (approve) {
            accessStatus[msg.sender][doctor] = AccessStatus.Granted;
            emit AccessGranted(msg.sender, doctor, uint64(block.timestamp));
        } else {
            accessStatus[msg.sender][doctor] = AccessStatus.Rejected;
            emit AccessRejected(msg.sender, doctor, uint64(block.timestamp));
        }
    }

    function revokeAccess(address doctor) external {
        require(accessStatus[msg.sender][doctor] == AccessStatus.Granted, "Not granted");
        accessStatus[msg.sender][doctor] = AccessStatus.Revoked;
        emit AccessRevoked(msg.sender, doctor, uint64(block.timestamp));
    }

    function hasAccess(address patient, address doctor) external view returns (bool) {
        return verifiedDoctors[doctor] && accessStatus[patient][doctor] == AccessStatus.Granted;
    }
}
```

**Contract rules:** keep it exactly this simple. Do not add upgradeability, tokens, or IPFS. Doctors who were `Rejected`/`Revoked` may request again (the `requestAccess` guard allows it).

## 4. API Specification (backend, base `/api`)

All protected routes need `Authorization: Bearer <JWT>`. All responses: `{ success: boolean, data?, message? }`.

### Auth — `/api/auth`
| Method | Path | Access | Purpose |
|---|---|---|---|
| POST | `/register` | public | Register patient or doctor. Body: `name, email, password, role, walletAddress`; doctors also `licenseNumber, specialization, hospital, experienceYears`. Patients get a generated `patientId`. Doctors create a `DoctorProfile` with `pending`. Admin role **cannot** be registered here. |
| POST | `/login` | public | Returns JWT (7d) + user. Doctors with `pending`/`rejected` status can log in but the response flags `doctorStatus`. |
| GET | `/me` | any | Current user (+ doctor profile). |
| PUT | `/wallet` | any | Update/link wallet address (must be unique, validated). |

### Admin — `/api/admin` (role: admin)
| Method | Path | Purpose |
|---|---|---|
| GET | `/doctors?status=pending` | List doctors by status. |
| GET | `/doctors/:id` | Doctor detail. |
| POST | `/doctors/:id/approve` | Body `{ txHash }`. Backend verifies receipt: tx succeeded, `to` = contract, emitted `DoctorVerified(doctor)`. Then calls `verifiedDoctors(wallet)` to double-check. Sets `approved`. |
| POST | `/doctors/:id/reject` | Body `{ reason, txHash? }`. Sets `rejected`. |
| GET | `/stats` | Counts: patients, doctors (by status), records, access requests. |

### Patient — `/api/patient` (role: patient)
| Method | Path | Purpose |
|---|---|---|
| GET | `/dashboard` | Counts + recent activity. |
| GET | `/access-requests?status=` | Requests addressed to this patient. |
| GET | `/granted` | Currently granted doctors. |

### Doctor — `/api/doctor` (role: doctor, approved)
| Method | Path | Purpose |
|---|---|---|
| GET | `/patients/search?patientId=MC-P-XXXXXX` | Exact match only. Returns `name`, `patientId`, `walletAddress` — **no medical data**. |
| GET | `/requests` | This doctor's requests and statuses. |
| GET | `/authorized-patients` | Patients with active grants (live-checked against chain). |
| GET | `/patients/:patientId/records` | Record metadata list. **Requires on-chain `hasAccess`.** |

### Records — `/api/records`
| Method | Path | Access | Purpose |
|---|---|---|---|
| POST | `/` | patient | `multipart/form-data` (`file`, `title`, `category`, `description`). Validate type (pdf/jpg/png) and size ≤ 10 MB. Hash → encrypt → save → create record (`chainStatus: pending`). Returns `{ record, fileHash, recordIdOnChain }` so the frontend can sign `registerRecord`. |
| POST | `/:id/confirm` | patient (owner) | Body `{ txHash }`. Verify receipt and `RecordRegistered` event args match; set `confirmed`. |
| GET | `/mine` | patient | Own records. |
| GET | `/:id/download` | owner patient OR doctor with on-chain access | Decrypt and stream the file. Logs `RECORD_VIEWED` for doctors. |
| POST | `/:id/verify` | owner patient OR doctor with access | Decrypt → rehash → compare with `getRecord`. Returns `{ status: "VERIFIED" \| "TAMPERED", localHash, chainHash }`. |
| DELETE | `/:id` | patient (owner) | Soft-delete only if you choose to implement; the on-chain hash remains. **Optional — skip in v1.** |

### Access — `/api/access`
| Method | Path | Access | Purpose |
|---|---|---|---|
| POST | `/request` | doctor (approved) | Body `{ patientId, reason, txHash }`. Verify `AccessRequested` event; create `AccessRequest(pending)`. |
| POST | `/:id/respond` | patient | Body `{ approve: boolean, txHash }`. Verify `AccessGranted`/`AccessRejected`; update status. |
| POST | `/:id/revoke` | patient | Body `{ txHash }`. Verify `AccessRevoked`; set `revoked`. |

### Audit — `/api/audit`
| Method | Path | Access | Purpose |
|---|---|---|---|
| GET | `/` | any | Role-scoped logs: patient → own; doctor → own actions; admin → all. Supports `?action=&page=&limit=`. |

### Security middleware (in `app.js`)
`helmet`, `cors` (origin = `FRONTEND_URL`), `express-rate-limit` (100 req/15 min global; 10/15 min on `/auth/login` and `/auth/register`), `express-mongo-sanitize`, JSON body limit `1mb`, `morgan` in dev.

11. `controllers/audit.controller.js` + route: role-scoped paginated list.

**Exit Criteria (test with Postman/Thunder Client or curl):**
- Register patient (receives `patientId`), register doctor (profile `pending`), login both, `GET /me` works.
- Admin login works after seed.
- Calling an admin route with a patient token returns 403; without a token returns 401.
- Duplicate email/wallet returns a clean 409/400.

### PHASE 4 — Doctor Verification (Backend + Chain Integration)

**Goal:** Admin can approve/reject doctors; approval is anchored on-chain.

**Steps:**
1. `config/blockchain.js`: create `JsonRpcProvider(AMOY_RPC_URL)` and a **read-only** `Contract(address, abi, provider)`.
2. `services/chain.service.js` functions:
   - `getReceiptOrThrow(txHash)` — waits briefly/polls; throws if missing or `status !== 1`; ensures `receipt.to` equals the contract address.
   - `findEvent(receipt, eventName)` — parse logs with `contract.interface`.
   - `isDoctorVerified(address)`, `hasAccess(patient, doctor)`, `getRecordOnChain(recordId)`.
   - `assertTxSignedBy(receipt/tx, expectedAddress)` — compare `tx.from` (lowercased) to the expected wallet. **Every confirm endpoint must call this.**
3. `admin.controller.js` + routes per Section 4: list, detail, approve (with `txHash` verification as described), reject, stats.
4. `doctor.controller.js`: profile and status. Add middleware `requireApprovedDoctor` (checks `DoctorProfile.status === 'approved'`).
5. Audit: `DOCTOR_REGISTERED` (in Phase 3), `DOCTOR_APPROVED`, `DOCTOR_REJECTED` with `txHash`.

**Exit Criteria:**
- Manually call `verifyDoctor` via a Hardhat console script with the admin key, then call `POST /admin/doctors/:id/approve` with that `txHash` → doctor becomes `approved`.
- A bogus/other-contract `txHash` or a tx signed by a non-admin is rejected.

### PHASE 5 — Medical Records, Encryption, Hashing

**Goal:** Patients upload encrypted records; hashes anchored on-chain; verification works.

**Steps:**
1. `services/crypto.service.js`:
   - `sha256Hex(buffer)` → `"0x" + hex`.
   - `encryptBuffer(buffer)` → `{ encrypted, iv, authTag }` using `aes-256-gcm`, 12-byte random IV, key = `Buffer.from(FILE_ENCRYPTION_KEY, 'hex')`.
   - `decryptBuffer(encrypted, iv, authTag)`.
2. `middleware/upload.js`: multer **memoryStorage**, 10 MB limit, `fileFilter` allowing only `application/pdf`, `image/jpeg`, `image/png` (also check extension).
3. `record.controller.js`:
   - `upload`: hash plaintext → encrypt → write to `storage/<uuid>.enc` → create `MedicalRecord` (`chainStatus: pending`) → compute `recordIdOnChain = ethers.id(record._id.toString())` → respond with `{ record, fileHash, recordIdOnChain }`. Reject the upload if the user has no wallet linked.
   - `confirm`: owner check; `getReceiptOrThrow`; `assertTxSignedBy(patient.wallet)`; find `RecordRegistered`; assert `recordId` and `fileHash` match DB; update `chainStatus`, `txHash`, `blockNumber`; audit `RECORD_UPLOADED` + `RECORD_CHAIN_CONFIRMED`.
   - `mine`, `download` (owner or doctor via on-chain `hasAccess` — also add doctor path now but test it in Phase 6), `verify`.
   - Set download headers: `Content-Type` from `mimeType`, `Content-Disposition` with the original name. Never expose `storedName`.
4. `verify`: decrypt → rehash → `getRecordOnChain` → compare both with DB hash. Return `VERIFIED` or `TAMPERED`; audit `RECORD_VERIFIED` / `RECORD_TAMPER_DETECTED`.
5. `patient.controller.js`: dashboard counts.

**Exit Criteria:**
- Upload a PDF via Postman → file on disk is unreadable ciphertext → frontend-less test: sign `registerRecord` with a script, call `confirm` → status `confirmed`.
- `verify` returns `VERIFIED`. Then **manually flip a byte in the `.enc` file** (or the DB hash) → `verify` returns `TAMPERED`.
- Wrong user cannot download another patient's record (403).

### PHASE 6 — Consent and Access Control (Backend)

**Goal:** Full request → grant/reject → revoke lifecycle, enforced by chain state.

**Steps:**
1. `access.controller.js`:
   - `request`: approved doctor only; resolve `patientId` → patient; verify receipt signed by the doctor's wallet and `AccessRequested(patient, doctor)` event; reject if an active pending/granted DB request exists; create `AccessRequest(pending)`; audit `ACCESS_REQUESTED`.
   - `respond`: patient owner of request; verify the `AccessGranted`/`AccessRejected` event, signer = patient; update; audit.
   - `revoke`: verify `AccessRevoked`, signer = patient; update; audit.
2. `patient.controller.js`: `access-requests`, `granted`.
3. `doctor.controller.js`: `patients/search` (exact `patientId` only, rate-limited), `requests`, `authorized-patients`, `patients/:patientId/records` — all gated by the live `hasAccess` call. Never trust the DB alone for access.
4. Ensure `record.download` and `record.verify` for doctors call `hasAccess` every time and log `RECORD_VIEWED`.

**Exit Criteria (scripted end-to-end through the API + wallet scripts):**
- Doctor requests → patient sees pending → grants → doctor lists records and downloads → patient revokes → doctor's next download returns 403 immediately.
- Unverified/pending doctor cannot request. Doctor cannot access patient B's records with patient A's grant.

### PHASE 9 — Frontend: Patient Flows

## 7. Instructions for Antigravity (agent behavior)

1. Execute **one phase at a time**; after each, run the Exit Criteria checks and report results before continuing.
2. Do not invent additional features, libraries, or architecture changes beyond this document. If something is ambiguous, choose the simplest option consistent with Section 0 and note it in the README.
3. Never commit `.env` files or private keys. Use `.env.example` for templates.
4. Never store medical files on-chain or in plaintext on disk.
5. Never let the backend sign transactions on behalf of users.
6. Every endpoint that accepts a `txHash` must verify: receipt success, correct contract, expected event, and that the signer matches the expected wallet.
7. Keep code modular per the file structure; keep controllers thin and put logic in services.
8. Use `async/await` with `asyncHandler`; no unhandled promise rejections.
9. Add concise comments only where logic is non-obvious (hash/event verification, access checks).
